# اصلاحات امنیتی اکتبر ۲۰۲۶

## تغییرات

- پاسخ جزئیات خانواده برای سمت‌های بدون مجوز پروفایل کامل، فقط فیلدهای خلاصهٔ مجاز را برمی‌گرداند. اطلاعات پزشکی، کد ملی، شماره کارت، اطلاعات اعضا و محتوای یادداشت‌ها از این پاسخ حذف می‌شوند. خروجی چاپ نیز به همان مجوز پروفایل کامل نیاز دارد.
- حوزهٔ دسترسی رابط پیش از شروع بررسی درخواست مالی و حذف/جایگزینی اسناد کنترل می‌شود.
- ویرایش، تصمیم‌گیری و پرداخت درخواست مالی روی یک ردیف مشترک قفل می‌گیرند و وضعیت جاری را داخل تراکنش بررسی می‌کنند؛ درخواست مالی آرشیوشده قابل تغییر نیست.
- ثبت و نمایش رمز متنی در همهٔ محیط‌ها حذف شده است؛ متغیر قدیمی `DEV_CAPTURE_PASSWORDS` دیگر قابلیتی را فعال نمی‌کند.
- Migration جدید `032_purge_plaintext_passwords.sql` اطلاعات ثبت‌شدهٔ قبلی را پاک می‌کند، نشست‌های حساب‌های مربوط را باطل می‌کند، تغییر رمز را اجباری و ثبت رکورد متنی جدید را ممنوع می‌کند.
- پیش‌نویس پرونده فقط در `sessionStorage` همان تب، با کلید مختص کاربر و انقضای هشت‌ساعته نگهداری می‌شود؛ خروج از حساب پیش‌نویس‌ها را پاک می‌کند. دادهٔ قدیمی `localStorage` هنگام بارگذاری نسخهٔ جدید حذف می‌شود.
- محاسبهٔ روز سررسید با نیمه‌شب تهران هماهنگ و خطای TypeScript تاریخ‌ها رفع شده است.
- نسخهٔ کش Service Worker تغییر کرده تا فایل‌های امنیتی جدید جایگزین نسخه‌های کش‌شده شوند.

## استقرار

1. پیش از ارتقا، پشتیبان رمزگذاری‌شده در محل امن خارج از مخزن تهیه کنید.
2. نسخهٔ جدید را دریافت و مطابق راهنمای نصب، `npm run migrate` را اجرا کنید؛ Migration قبلی را دستی تغییر ندهید.
3. برنامه را با نسخهٔ جدید راه‌اندازی و ورود، دسترسی سمت‌ها و گردش مالی را در محیط آزمایشی بررسی کنید.
4. حساب‌هایی که رمز متنی آن‌ها قبلاً ثبت شده، باید دوباره وارد شوند و رمز متفاوتی انتخاب کنند.
5. روی مرورگرهای مشترک، بارگذاری نسخهٔ جدید و پاک‌شدن پیش‌نویس قدیمی را تأیید کنید.

## پشتیبان‌های منتشرشده: اقدام تکمیلی مالک مخزن

حذف `before-b5.dump`، `before-c1.dump` و ZIP قدیمی از درخت فعلی، نسخه‌های قبلی آن‌ها را از تاریخچهٔ Git، کلون‌ها، فورک‌ها یا کش‌ها پاک نمی‌کند. ZIP نیز هر دو dump را در خود داشت.

- اگر داده‌ها واقعی بوده‌اند، رمز حساب‌های مربوط و هر رازِ منتشرشده را تغییر دهید؛ پاک‌کردن فایل به‌تنهایی جایگزین این اقدام نیست.
- پاک‌سازی تاریخچه نیازمند هماهنگی همهٔ همکاران، بررسی همهٔ شاخه‌ها و تگ‌های مرتبط و بازنویسی کنترل‌شدهٔ تاریخچه است. پس از آن ممکن است همکاری GitHub برای پاک‌سازی کش/ارجاع‌های باقی‌مانده لازم باشد.
- این تغییرات شامل force-push یا بازنویسی تاریخچه نیستند و به‌تنهایی نرم‌افزارِ در حال اجرا را ارتقا نمی‌دهند.

## تست

```bash
npm ci
npm run typecheck
npm run test:regressions
npm run test:local-fixes
npm run test:security
npm run test:security:integration
```

تست امنیت یکپارچه به‌صورت پیش‌فرض PostgreSQL موقت را با Testcontainers اجرا می‌کند. بدون Docker می‌توان `TEST_DATABASE_URL` را به یک دیتابیس خالی، مجزا و دورریختنی با نام شامل `test` اشاره داد. این تست روی دیتابیس دارای جدول `users` اجرا نمی‌شود و برای دیتابیس واقعی/توسعه مناسب نیست. تست‌های امنیت جدید جایگزین کل مجموعهٔ قدیمی Integration یا آزمون پذیرش رابط کاربری نیستند.
