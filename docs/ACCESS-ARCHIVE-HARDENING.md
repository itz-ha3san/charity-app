# قواعد دسترسی و بایگانی پرونده

## تغییرات این مرحله

- `src/scope.ts` مرجع مشترک دامنه خانواده، بازبینی نظارت و دسترسی تخصصی است. نمایش صندوق اقدام نیز از دامنه جاری خانواده استفاده می‌کند، نه صرفاً انتساب قدیمی اقدام.
- `src/familyRouteAccess.ts` پس از احراز هویت، خانواده واقعی منابع وابسته را از دیتابیس پیدا می‌کند. مالکیت قدیمی اقدام، گزارش یا پرونده مالی جایگزین مجوز جاری خانواده نیست. این کنترل، مکمل مجوز عملیاتی هر مسیر است و جای آن را نمی‌گیرد.
- دسترسی خلاصه خانواده به معنای دسترسی به ارزیابی، نتیجه، سابقه یا اسناد پرونده تخصصی نیست. فهرست تخصصی برای نقش فاقد مجوز با `restricted: true` و آرایه‌های خالی پاسخ می‌دهد؛ رابط کاربری علت محدودیت را نمایش می‌دهد.
- خروجی جامع و خط زمانی، داده تخصصی و دلیل دانلود سند تخصصی را برای رابط نمایش نمی‌دهند. موعد پیگیری استخراج‌شده از پرونده تخصصی نیز تابع همین دامنه است.
- پاسخ‌های `/api/` و `/auth/` با `Cache-Control: private, no-store` ارسال می‌شوند. این تغییر داده‌ای را که قبلاً خارج از برنامه ذخیره شده پس نمی‌گیرد.

## دسترسی به پرونده تخصصی

| نقش | دسترسی |
| --- | --- |
| مدیر سامانه و مدیرعامل | همه حوزه‌ها |
| معاون درمان | فقط حوزه درمان |
| معاون آموزش | فقط حوزه آموزش |
| مسئول درمان/آموزش | فقط پرونده حوزه خود که به خودش و دقیقاً همان ارجاع باز یا درحال‌انجام متصل باشد |
| رابط، مشاهده‌گر، مالی و معاون نظارت | بدون محتوای پرونده تخصصی |

بسته‌شدن، لغو یا واگذاری ارجاع مرتبط، دسترسی مسئول قبلی را قطع می‌کند؛ داشتن ارجاع دیگری برای همان خانواده کافی نیست. مسئول قبلی نمی‌تواند برای بازیابی دسترسی، ارجاع بسته را دوباره باز کند. پس از تکمیل و بسته‌شدن ارجاع، درخواست هزینه تخصصی را معاون همان حوزه یا مدیر مجاز ثبت می‌کند، مگر اینکه مسئول هنوز دامنه معتبر خانواده داشته باشد. قوانین قبلی دسترسی به پروفایل پایه خانواده و تأیید تغییرات خانواده جدا هستند و در این مرحله بازطراحی نشده‌اند.

## بایگانی

مهاجرت `033_family_archive_guards.sql` حفاظت را علاوه بر API، در PostgreSQL نیز اعمال می‌کند:

- خانواده بایگانی‌شده و ۲۰ جدول وابسته تجاری فقط‌خواندنی‌اند؛ شامل یادداشت، عضو، سند، ارجاع، اقدام، گزارش، پرونده تخصصی، پرونده مالی، پرداخت، تخصیص کمک و تراکنش انبار.
- درج، ویرایش، حذف و جابه‌جایی ردیف از/به خانواده بایگانی‌شده رد می‌شود. نوشتن گروهی هم استثنا نیست.
- قفل ردیف خانواده، رقابت نوشتن با بایگانی هم‌زمان را هماهنگ می‌کند. خطای دیتابیس `P7501` در API به `409 FAMILY_ARCHIVED` تبدیل می‌شود.
- بازگشایی مجاز فقط پرچم بایگانی و زمان به‌روزرسانی را تغییر می‌دهد؛ تغییر پروفایل یا مالکیت هم‌زمان با آن مجاز نیست.
- خواندن تاریخی همچنان تابع مجوز نقش است. لاگ ممیزی و ثبت دسترسی قابل افزودن می‌مانند. پیام سازمانی درباره خانواده، ویرایش رکورد خانواده محسوب نمی‌شود و سیاست فرستنده/گیرنده مستقل دارد.
- داده مرجع مشترک مانند مشخصات کاربر یا سرپرست با بایگانی نسخه‌بندی نمی‌شود. حذف کاربری که مستلزم تغییر انتساب رکورد بایگانی‌شده است ممکن است رد شود؛ برای خروج نیرو از غیرفعال‌سازی استفاده شود و تغییر تاریخی فقط با بازگشایی مجاز انجام شود.

## استقرار

1. پیش از ارتقا پشتیبان دیتابیس تهیه و بازیابی آن بررسی شود؛ روی نسخه آزمایشی مشابه محیط واقعی تست شود.
2. در پنجره نگهداری، ترافیک نوشتن متوقف شود و نسخه جدید کد دریافت شود.
3. با تنظیمات اتصال همان محیط، `npm run migrate` اجرا شود. مهاجرت جدید فقط تابع/تریگر اضافه می‌کند و داده تجاری را حذف یا بازنویسی نمی‌کند؛ گرفتن قفل می‌تواند تا پایان تراکنش‌های جاری منتظر بماند.
4. سرویس با نسخه جدید راه‌اندازی مجدد شود و نقش‌ها، بایگانی/بازگشایی و مسیرهای مجاز کنترل شوند. نسخه کش پوسته به v94 تغییر کرده است.
5. حفاظت کامل دیتابیس به اجرای مهاجرت 033 وابسته است. پوش کد به گیت‌هاب به معنی استقرار یا اجرای مهاجرت روی سرور نیست.

این مرحله شامل پاک‌سازی تاریخچه گیت، چرخش اسرار قدیمی، بازطراحی UI یا ممیزی جامع زیرساخت نیست. کنترل اولیه دامنه در همه مسیرها به‌تنهایی تضمین اتمی‌بودن تمام تغییرات هم‌زمان مجوز نیست؛ مسیر تخصصی قفل‌های ارجاع خود را حفظ می‌کند و رقابت بایگانی در سطح دیتابیس محافظت می‌شود.

## اعتبارسنجی

- `npm run typecheck`
- `npm run test:security:integration` — ۳۲ تست یکپارچه، دیتابیس خالی و دورریختنی؛ `TEST_DATABASE_URL` باید نام شامل `test` داشته باشد. در نبود این متغیر، Testcontainers به Docker نیاز دارد.
- `npm run test:regressions` — ۲۳ تست
- `npm run test:local-fixes` — ۸ تست
- `npm run test:security` — ۶ تست، شامل پارس اسکریپت‌های مرورگر
- آزمون ارتقا روی دیتابیس آزمایشی نسخه قبلی و اجرای دوباره مهاجرت، با ثابت‌ماندن هش و تعداد ردیف‌های ۵۱ جدول تجاری/کاربری انجام شد.

این مجموعه ۶۹ تست منتخب است؛ جایگزین کل `tests/integration.test.ts` قدیمی یا تست نفوذ و بررسی محیط عملیاتی نیست. دیتابیس تولید در اجرای این تست‌ها استفاده نشده است.
