# ساختار فرانت‌اند

## نقطه ورود و مرز قابلیت‌ها

کد اجرایی و CSS درون `index.html` به `public/app/` منتقل شده‌اند. کد پرونده، فرم خانواده، مالی، سازمان، گزارش، هشدار، پیگیری و اسناد فایل‌های موضوعی جدا دارند. فایل‌های `base.css` و `profile.css` در همان جای قبلی زنجیره cascade بارگذاری می‌شوند؛ پوسته CSS جدیدی روی لایه‌های قدیمی اضافه نشده است.

`manifest.json` فهرست صریح فایل‌های ضروری و ترتیب آن‌هاست. تعریف توابع از اتصال رویدادها جدا شده؛ `bootstrap.js` پس از تعریف قابلیت‌ها رویدادها را متصل و نشست را راه‌اندازی می‌کند. `api.js` کلاینت HTTP و ترجمه کدهای خطا را نگه می‌دارد.

**مرز سازگاری:** فایل‌های موضوعی فعلاً classic script هستند، نه ES module ایزوله. افزونه‌های قبلی به توابع `window` و متغیرهای مشترک وابسته‌اند؛ شکستن ناگهانی این قرارداد با این بازآرایی انجام نشده است. ترتیب ضروری اکنون صریح و با تست کنترل می‌شود، نه اینکه همه وابستگی‌های قدیمی حذف شده باشند. مهاجرت بعدی به state/API تزریقی و ES module باید قابلیت‌به‌قابلیت باشد؛ React پیش‌نیاز نیست.

## اجزای مشترک

- `ui.js`: busy، پیام فرم، toast و mount پنجره؛ استفاده از کلاس‌های سیستم طراحی موجود، نقش‌های دسترس‌پذیری، و یک runner برای جلوگیری از submit موازی.
- پنجره‌های استخراج‌شده و مدیریت کاربران از mount مشترک استفاده می‌کنند. پیام toast با `textContent` درج می‌شود و تایمر پیام قبلی نمی‌تواند پیام جدید را زود پاک کند.
- فرم پرداخت هنگام ارسال غیرفعال می‌شود. هر payload یک کلید idempotency تصادفی دارد؛ retry همان فرم و همان payload همان کلید را می‌فرستد. تغییر payload کلید جدید می‌سازد. این صرفاً مکمل قفل و کنترل سرور است؛ retry خودکار تراکنش نداریم.
- `lifecycle.js`: ناظر مشترک تغییرات body برای چهار enhancer عمومی، به‌جای چهار observer مستقل. observerهای محدود به یک جزء حفظ شده‌اند.
- مدیر پنجره در `advanced-ui.js` اکنون با بستن یا جایگزینی پنجره، listener صفحه‌کلید و قفل اسکرول را پاک می‌کند؛ برای هر پنجره observer دائمی تازه ساخته نمی‌شود.

## بارگذاری هنگام نیاز

`assets.js` فقط دو مسیر هم‌مبدأ و از پیش مشخص را بارگذاری می‌کند: مجموعه مدیریت/آموزش/ابزارها و رابط پیشرفته تأییدها. یک درخواست در حال اجرا بین فراخوانی‌ها مشترک است و خطای شبکه قابل تلاش مجدد است. این فایل‌ها هنگام ورود عادی دانلود نمی‌شوند. بارگذاری فایل مجوز دسترسی نیست؛ API همچنان مجوز هر درخواست را بررسی می‌کند.

Service Worker نسخه جدید، فایل‌های ضروری جدید را precache می‌کند. `/api/` و `/auth/` همچنان کش نمی‌شوند. صفحه ناوبری آفلاین اطلاعات پرونده نشان نمی‌دهد؛ فایل‌های lazy در اولین استفاده آفلاین تضمین‌شده نیستند.

## کنترل کیفیت

`npm run frontend:check` در build نیز اجرا می‌شود: ترتیب manifest، وجود assetها، syntax هر فایل و عدم تداخل نام‌های lexical، لینک‌های محلی و نبود بازگشت کد اجرایی به inline script. تست‌های واحد loader، lifecycle و ارسال هم‌زمان فرم و تست مرورگر دسکتاپ/موبایل برای گردش اصلی، lazy load، گم‌شدن پاسخ پرداخت و حالت آفلاین اضافه شده‌اند.

این گام بازطراحی UX روزانه نیست. همه CSSها و enhancerهای قدیمی حذف نشده‌اند؛ کم‌کردن لایه‌های باقی‌مانده باید با snapshot و تست قابلیت مربوط انجام شود، نه حذف کورکورانه ظاهر یا رفتارهای فعال.

در محیط localhost یا IP خصوصی، سیاست قبلیِ غیرفعال‌سازی Service Worker حفظ شده است. تست متمرکز آفلاین، worker را پس از بارگذاری صفحه صریحاً ثبت می‌کند تا خود worker و عدم کش API بررسی شوند؛ این به معنی فعال‌شدن خودکار آن در محیط توسعه نیست.
