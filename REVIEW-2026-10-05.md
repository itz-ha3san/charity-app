## Fixes applied
1. Activated the existing refinement layer in the frontend.
2. Made localStorage form autosave opt-in instead of automatic, preventing case/family data from being silently persisted in browser localStorage.
3. Fixed role-based navigation being reused after logout/login: the navigation is rebuilt for the current user, so admin controls do not remain visible for a lower-privilege user (and vice versa).
4. Added consistent frontend handling for expired sessions (401) and common authorization/validation errors.
5. Bumped the service-worker cache version and expanded the static cache to cover the assets actually referenced by the frontend, improving offline/PWA consistency.
6. Added production secret/TLS patterns to `.gitignore`.
7. Removed environment secrets, TLS private key material, and database dump files from this clean delivery package.

## Important security finding in the supplied archive
The supplied archive contained `.env.production`, a TLS private key under `deploy/certs/privkey.pem`, and PostgreSQL dump files. Even if they are test/local values, they should not be committed or shared as application source. If any of those secrets were ever used in a real environment, rotate them before deployment.

## Deployment note
Install dependencies fresh with `npm ci` (or let the Dockerfile run `npm install`) rather than copying the archived `node_modules` directory between Windows and Linux.
